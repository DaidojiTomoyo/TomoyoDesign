# 首页樱花背景：连续枝形与可见的生长过程

状态：2026-11-17，枝形、遮挡与开花时序已调整，局部视觉修正复审通过，四尺寸静态回退与浏览器收尾检查完成；生产构建受环境限制，未验证。用户选择：“都选 A，保留枝条向下生长，把枝形、遮挡和开花时序一起调整，让整体更自然一些，开始吧”。本轮完成与验收以当前实现及下方新增证据为准，上一轮局部 `ship` 不作为本轮结论。

## 当前方向与边界

- 樱花是贯穿首页的自然背景，从页面左上向下生长，绑定页面坐标；已经长出的部分随页面滚出视口。保留枝条真实延伸的过程，不改成只有现成木枝上的花朵开放。
- 保留蓝色隧道、四项组件演示、文案和顺序、水平 CTA、页脚与 `min(100% - 112px, 1328px)` 的居中内容边界。只做桌面布局，最小文档宽度 1200px，不新增花枝专用栏、独立段落或滚动距离。
- 先设计完整枝形，再检查局部避让：主枝连续、逐级变细，侧枝在真实节点分出，分叉角度、长度和曲率不等。花簇围绕短枝聚集。避免长空弧、平行吊线、方框折返和穿过 workflow 列缝的细长垂线。
- 主枝的连接关系在滚动中保持可读，不在没有可见边界的白色演示区域被突然截断。Metallic、Gallery 和 Image Focus 继续保留各自表面；主枝和主要花簇安排在真实留白中，文字与控件保持清楚。
- 主枝 → 次生枝 → 花梗 → 花苞 → 开花依次推进。局部时序参考节点与花簇的文档位置及视口高度，使关键展开阶段发生在看得清楚的位置；不能仅以统一全页进度延迟开花。原生反向滚动确定性还原，成熟木枝保持稳定。
- 花瓣保留薄、浅粉近白、浅缺口、不同朝向与重叠，花心与红褐花萼提供层次，少量新叶点缀。降低木枝与花瓣的重量差，分别检查白底、照片旁及蓝色 CTA。暂不锁定具体栽培品种，不宣称实拍级效果。
- 不加入滚动劫持、静止时持续摆动或自动花瓣雨。实时 canvas 保持视口大小，按需绘制；减少动效和渲染失效展示相同成熟构图的透明静态图。
- `DESIGN.md` 与 `.impeccable/design.json` 保持不变。本轮属于首页樱花的局部重构，不替换既有设计系统。

## 当前实现

- 移除矩形角点最短路径。一个连续主轴、五个长短不等的侧枝与两个真实子分叉构成八个木质轴；主枝斜向进出页面边缘，现有留白中的侧枝朝向与长度不同。第一条侧枝在母节点处单次向外分出，没有再次贴回主枝形成封闭孔。局部主枝返回段增加曲线平滑和采样，侧枝连接位置保持稳定。
- 22 组花簇保留 64 个花位：成熟时 49 朵全开、7 朵半开、8 个闭苞，另有 12 条短苞枝和 8 个轴梢苞。花簇在节点附近整体定位，文字及不透明演示区域用于检查空间，不生成矩形转角线路。
- 布局测量包含实际文字、Metallic、Gallery、Image Focus 的不透明表面与视口高度。主枝和主要花簇保持在真实留白内，避免无边界白色面板造成截断；既有正文宽度、演示尺寸与文档高度不变。
- 生长与开放按文档高度、视口高度和节点位置映射。主枝生长前沿约在视口高度的 82%，侧枝在母节点形成后展开，花梗与花苞先于花瓣。测试约束开放开始时位于视口 70% 高度以内，结束时尚未越过 38%，并在全页末端前完成。成熟木枝不因视口高度变化而移位。
- GSAP 使用 `scrub: true`，滚动绘制前同步进度，取消额外的 0.25 秒追赶过程。场景仍按需绘制，不增加静止时摆动。`picture` 父元素明确定位；木枝明暗对比减弱，花瓣喉部与重叠阴影加强。
- 最终几何为 65,239 个顶点、91,200 个三角形，仍使用 Uint16 索引；画布保留 1,250,000 像素预算。此前 CPU 采样早于最后的主枝采样和节点修正，不作为当前性能结果，也不代表 GPU 帧率。
